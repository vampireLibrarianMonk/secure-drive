# Independent Recovery (spec §6)

**Mandatory requirement.** The encrypted documents must never become
permanently dependent on the Emergency Archive application. If this project
disappears 15 years from now, a technically competent person with:

- the USB drive,
- the password,
- standard open-source recovery software,
- and `RECOVERY-INSTRUCTIONS.txt` (in the drive's `public/` folder),

must be able to recover the documents.

## Where recovery instructions live

1. `public/RECOVERY-INSTRUCTIONS.txt` on every USB drive — human-readable,
   no secrets, regenerated by the build (and exportable from Setup Mode).
2. This document — the engineering source of truth and checklist.

A draft of the on-drive file is installed by `scripts/new-usb.ps1`; it is
clearly marked DRAFT until the Phase 0 vault decision is finalized.

## Required contents of the final instructions

- Encryption format and format/version (from `docs/CRYPTOGRAPHY.md` decision).
- Which files on the drive hold encrypted data (`vault\...`).
- Compatible recovery software (names + where to obtain it, favoring
  long-lived, widely mirrored projects).
- Step-by-step manual unlock/decrypt procedure.
- Never: the password, key material, or anything else secret.

## Author checklist (when the format decision lands)

- [ ] Perform a full recovery exercise using ONLY third-party open-source
      software and the instructions file (no Emergency Archive code).
- [ ] Verify the instructions work on a clean Windows VM without Internet.
- [ ] Verify version numbers referenced in the file match the format version
      written on the drive.
- [ ] Add the exercise to the release checklist and repeat per major release.
