# Reference images

Drop screenshots here to make them appear in the guides. Each image spot in the
docs is marked with an HTML comment describing exactly what to capture, followed
by a Markdown image reference pointing at a file in **this** folder.

## How it works

- The docs reference images by a fixed **slug**, e.g.
  `![...](../reference_images/create-archive-screen.png)`.
- To fill a spot, save your screenshot as a **PNG** with that exact name in this
  folder (for example `create-archive-screen.png`). No doc edits needed — the
  image simply shows up.
- Keep the names exactly as listed below (lowercase, hyphens, `.png`).

## Regenerating the app screenshots automatically

The app screenshots below are **real captures of the real UI**, generated by
[`tools/CaptureScreens`](../tools/CaptureScreens) — a headless driver that
seeds a scratch vault with **fake sample data** (Alex Doe / example.org
addresses, SAMPLE policy numbers), walks the app through each documented state,
and saves the PNGs here. Re-run it whenever the UI changes:

```powershell
# From the repo root (needs Docker Desktop running; no host SDK required):
docker run --rm -v "${PWD}:/src" -e NUGET_PACKAGES=/tmp/nuget `
  mcr.microsoft.com/dotnet/sdk:10.0 bash /src/tools/CaptureScreens/run-capture.sh
```

The Windows File Explorer shot comes from `tools/CaptureScreens/capture-explorer.ps1`
(runs on the host; captures only the Explorer window rectangle, never the whole
desktop). Because everything is seeded fake data, these images are safe to
commit publicly.

## Tips for good screenshots

- Use realistic but **fake** sample data — never real passwords, account
  numbers, or personal documents (these images may be committed publicly).
- Crop to the app window; PNG keeps text crisp.
- If you rename a slug, update the matching reference in the doc too.
